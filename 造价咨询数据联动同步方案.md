### 二、存在的问题

#### ❌ 问题1：数据冗余
- **7个模型都存储了** `project_code`、`project_name`、`project_type` 等基础信息
- 每次新增项目需要在7个表中分别创建记录
- 修改项目名称需要在7个表中同步更新

#### ❌ 问题2：缺乏外键关联
- 当前使用 `project_code` 字符串字段关联，而非外键
- **无法保证数据完整性**：可能在某个子表中输入不存在的项目编号
- **无法级联删除**：删除项目信息时，子表数据会变成孤儿记录

#### ❌ 问题3：数据不同步风险
- 当 `CostProjectInfo` 中的信息更新时，其他6个子表不会自动同步
- 例如：修改了项目名称，其他6个表中的 `project_name` 不会自动更新

#### ❌ 问题4：查询效率低
- 需要跨表查询时，只能使用 `project_code` 进行 `JOIN` 或多次查询
- 无法利用Django ORM的外键关联查询优化

## 解决方案

### 方案A：保持当前设计 + 数据同步机制（推荐用于快速上线）

#### 优点
- ✅ 无需修改数据库结构
- ✅ 各子模块独立性强，可单独维护
- ✅ 适合初期快速开发

#### 实现方式

**1. 创建数据同步工具类**

创建文件：`eims_app/utils/cost_data_sync.py`

```python
from django.db import transaction
from ..models import (
    CostProjectInfo,
    CostTaskPlan,
    CostTaskImplementation,
    CostReviewResult,
    CostPaymentStatus,
    CostProjectArchive,
    CostRemunerationDistribution
)

class CostDataSync:
    """造价咨询数据同步工具"""
    
    @staticmethod
    @transaction.atomic
    def sync_project_info_to_submodules(project_info):
        """
        当项目信息更新时，同步到所有子模块
        
        Args:
            project_info: CostProjectInfo 实例
        """
        submodules = [
            CostTaskPlan,
            CostTaskImplementation,
            CostReviewResult,
            CostPaymentStatus,
            CostProjectArchive,
            CostRemunerationDistribution
        ]
        
        for model_class in submodules:
            # 查找是否存在对应项目
            record = model_class.objects.filter(
                project_code=project_info.project_code
            ).first()
            
            if record:
                # 更新存在记录的公共字段
                record.project_name = project_info.project_name
                record.project_type = project_info.project_type
                record.save(update_fields=['project_name', 'project_type'])
            # 如果不存在，不自动创建（由业务逻辑决定何时创建）
    
    @staticmethod
    def sync_all_to_submodules():
        """
        批量同步：将所有项目信息同步到子模块
        用于数据修复或初始化
        """
        project_infos = CostProjectInfo.objects.all()
        count = 0
        
        for project_info in project_infos:
            CostDataSync.sync_project_info_to_submodules(project_info)
            count += 1
        
        return count
```

**2. 在模型中自动触发同步**

修改 `eims_app/models/model_cost_sub_modules.py`，在 `CostProjectInfo` 中添加 `save()` 方法：

```python
class CostProjectInfo(models.Model):
    # ... 现有字段 ...
    
    def save(self, *args, **kwargs):
        """保存时触发同步"""
        is_new = self.pk is None
        super().save(*args, **kwargs)
        
        # 如果是更新（非新增），触发同步到子模块
        if not is_new:
            from ..utils.cost_data_sync import CostDataSync
            # 异步执行同步，避免阻塞
            try:
                CostDataSync.sync_project_info_to_submodules(self)
            except Exception as e:
                # 记录日志但不影响主流程
                import logging
                logger = logging.getLogger(__name__)
                logger.error(f"数据同步失败: {e}")
```

**3. 创建数据一致性检查命令**

创建文件：`eims_app/management/commands/check_cost_data_consistency.py`

### 方案B：重构为外键关联模型（推荐用于长期维护）

#### 优点
- ✅ 数据完整性有保障（数据库级别的外键约束）
- ✅ 无数据冗余，存储空间优化
- ✅ 查询效率高（ORM优化）
- ✅ 级联删除/更新自动化

#### 缺点
- ⚠️ 需要数据库迁移（可能有停机时间）
- ⚠️ 需要修改大量视图代码
- ⚠️ 需要数据迁移脚本

#### 实现方式

**1. 修改模型结构**

```python
# 只保留一个主表，其他子表通过外键关联

    """造价咨询项目信息主表"""
    project_code = models.CharField("项目编号", max_length=50, unique=True)
    project_name = models.CharField("项目名称", max_length=200)
    project_type = models.CharField("项目类型", max_length=20)
    # ... 其他公共字段 ...

class CostTaskPlan(models.Model):
    """造价咨询任务计划表"""
    # 外键关联到主表
    project = models.ForeignKey(
        CostProjectInfo,
        on_delete=models.CASCADE,  # 删除项目时级联删除
        related_name='task_plans'
    )
    # 只保留任务计划特有的字段
    compiler = models.CharField("编制人", max_length=50)
    first_reviewer = models.CharField("一审人员", max_length=50)
    # ... 不需要 project_code, project_name, project_type ...
```

### 方案C：混合方案（推荐，平衡实用性与可维护性）
