# 一人多项目功能实现说明

## ✅ 问题解决

### 原问题
- 同一个人只能分配到一个项目
- 无法实现跨项目兼职管理
- 可视化分配页面不支持一人多项目

### 解决方案
**核心设计：**
1. **Personnel.project** 字段作为"当前主要项目"（可选）
2. **PersonnelAllocation** 记录所有项目分配历史（支持一人多项目）
3. 同一人员在同一项目只能有一个有效分配
4. 支持将同一个人分配到多个不同项目

---

## 📊 数据模型设计

### 1. Personnel（项目人员）
```python
# 主要项目字段（可选，用于显示当前主要归属）
project = models.ForeignKey('Project', ..., verbose_name='主要项目')
project_code = models.CharField(max_length=50, verbose_name='项目编号')
department = models.CharField(max_length=100, verbose_name='部门')
position = models.CharField(max_length=100, verbose_name='岗位')
```

**用途：**
- 快速查询某人当前主要在哪个项目
- 简化常用查询场景
- 可选字段，允许为空

### 2. PersonnelAllocation（人员分配记录）
```python
# 新增字段
allocation_department = models.CharField(max_length=100, verbose_name='分配部门')

# 原有字段
personnel = models.ForeignKey('Personnel', ...)  # 人员
to_project = models.ForeignKey('Project', ...)   # 分配到的项目
from_project = models.ForeignKey('Project', ...) # 原项目
allocation_position = models.CharField(...)      # 岗位
allocation_status = models.CharField(...)        # 状态
```

**用途：**
- 记录完整的分配历史
- 支持一人多项目（通过多条记录）
- 每个项目一条分配记录

## 🔄 业务流程

### 场景 1：新员工首次分配
1. 创建 Personnel 记录（基本信息）
2. 设置 `project` = 项目 A（主要项目）
3. 创建 PersonnelAllocation 记录：
   - personnel = 该员工
   - to_project = 项目 A
   - from_project = None
   - allocation_department = 工程部
   - allocation_position = 技术员

### 场景 2：员工兼职另一个项目
1. **不修改** Personnel.project（保持主要项目）
2. 创建新的 PersonnelAllocation 记录：
   - personnel = 该员工
   - to_project = 项目 B
   - from_project = 项目 A（或其他）
   - allocation_department = 技术部
   - allocation_position = 技术负责人

### 场景 3：员工从项目 C 调到项目 D
1. 更新 Personnel.project = 项目 D（更新主要项目）
2. 创建 PersonnelAllocation 记录：
   - to_project = 项目 D
   - from_project = 项目 C
   - allocation_status = 'allocated'

### 场景 4：查看员工所有项目分配
```python
# 查询某员工的所有分配记录
employee_allocations = PersonnelAllocation.objects.filter(
    personnel=some_personnel,
    allocation_status='allocated'
)

# 结果包含该员工在所有项目的分配信息
```

## 📋 使用指南

### 方式 1：可视化分配界面
1. 访问：侧边栏 → 人员管理 → 可视化分配
2. 勾选要分配的人员（支持多选）
3. 点击"分配到项目"按钮

## ⚠️ 注意事项

### 1. 数据一致性
- Personnel.project 应该与最新的 PersonnelAllocation 记录保持一致（可选）
- 建议在 UI 中提供"设置为主要项目"功能

### 2. 性能考虑
- 查询某人所有项目：使用 `select_related('to_project')`
- 查询某项目所有人：使用 `filter(to_project=xxx)`

### 3. 权限控制
- 只有超级管理员可以进行人员分配
- 项目经理可查看本项目人员
- 员工本人可查看所有自己的分配记录
