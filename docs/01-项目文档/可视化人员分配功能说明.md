# 可视化人员分配功能说明

## 功能概述

新增了**可视化人员分配**功能，提供直观、高效的交互式人员分配界面，支持：
- ✅ **复选框选择** - 批量勾选人员
- ✅ **双击快速选择** - 双击人员行选中/取消
- ✅ **两步分配流程** - 先分配到部门，再分配到项目
- ✅ **自动数据同步** - 分配后自动更新花名册、项目人员等数据
- ✅ **人员召回** - 一键将人员从项目撤回待分配状态

---

## 访问路径

### 方式 1：从人员花名册进入
1. 访问人员花名册页面：`/personnel/`
2. 点击 **"可视化分配"** 按钮（蓝色信息按钮）

### 方式 2：从项目详情进入
1. 访问项目详情页面：`/projects/<id>/`
2. 切换到"项目人员"标签页
3. 点击 **"可视化分配"** 按钮（黄色警告按钮）

### 方式 3：直接访问
URL: `http://localhost:8000/personnel/allocation-visual/`

---

## 界面布局

### 左侧面板：待分配人员
- **黄色标题栏** - 显示"待分配人员"及数量
- **筛选工具** - 按关键词、部门筛选
- **批量操作按钮**:
  - 全选 - 一键勾选所有可见人员
  - 分配到部门 - 打开部门分配对话框
  - 分配到项目 - 打开项目分配对话框
- **人员列表** - 显示未分配到项目的人员
  - 字段：编号、姓名、部门、岗位、手机
  - 支持双击快速选择

### 右侧面板：已分配人员
- **绿色标题栏** - 显示"已分配人员"及数量
- **批量召回按钮** - 批量撤回选中人员
- **人员列表** - 显示已分配到项目的人员
  - 字段：编号、姓名、部门、项目、岗位、操作
  - 每行有"召回"按钮可单独撤回

## 操作流程

### 场景 1：批量分配到部门

**步骤**:
1. 在左侧"待分配人员"列表中勾选需要分配的人员（或双击选择）
2. 点击 **"分配到部门"** 按钮
3. 在弹出的对话框中选择部门：
   - 工程部
   - 技术部
   - 质量部
   - 安全部
   - 物资部
   - 财务部
   - 综合办
   - 其他
4. 点击 **"确认分配"** 按钮

**结果**:
- ✅ 人员部门字段自动更新
- ✅ 页面自动刷新显示最新状态

---

### 场景 2：批量分配到项目

**步骤**:
1. 在左侧"待分配人员"列表中勾选需要分配的人员
2. 点击 **"分配到项目"** 按钮
3. 在弹出的对话框中填写:
   - **选择项目** (必选) - 从下拉列表选择目标项目
   - **分配岗位** (可选) - 如：技术员、施工员、安全员等
   - **分配日期** (默认今天) - 分配生效日期
4. 点击 **"确认分配"** 按钮

**后台处理**:
1. ✅ 更新人员的 `project` 和 `project_code` 字段
2. ✅ 创建 `PersonnelAllocation` 分配记录
3. ✅ 记录原项目和新项目信息
4. ✅ 自动设置分配状态为"已分配"
5. ✅ 记录操作人和操作时间

**数据同步**:
- ✅ **人员花名册** - 显示最新项目分配状态
- ✅ **项目人员列表** - 新增人员记录
- ✅ **项目详情页** - 项目人员数量自动增加
- ✅ **人员分配列表** - 新增分配记录

---

### 场景 3：人员召回

#### 单个召回
**步骤**:
1. 在右侧"已分配人员"列表中找到目标人员
2. 点击该行的 **"召回"** 按钮
3. 确认召回操作

**结果**:
- ✅ 人员的 `project` 字段清空
- ✅ 创建召回类型的分配记录
- ✅ 分配状态标记为"已召回"
- ✅ 人员回到左侧"待分配人员"列表

#### 批量召回
**步骤**:
1. 勾选右侧"已分配人员"中的多个人员
2. 点击 **"批量召回"** 按钮
3. 确认批量召回操作

**结果**:
- ✅ 所有选中人员被召回
- ✅ 为每个人创建召回记录

## 交互特性

### 1. 双击选择
- 在人员列表的任意行双击，可快速选中/取消该行
- 选中的行会高亮显示
- 复选框状态与双击操作同步

### 2. 全选功能
- 点击表头的全选复选框，可一键选择当前列表的所有人员
- 再次点击取消全选

### 3. 实时计数
- 模态框中实时显示已选中的人员数量
- 例如："将选中 **3** 名人员分配到选定项目"

### 4. 操作反馈
- 所有操作都有明确的提示信息
- 成功：显示成功消息和受影响的人数
- 失败：显示错误原因

## 数据模型联动

### Personnel (人员花名册)
```python
# 分配时自动更新
personnel.project = project  # 关联项目
personnel.project_code = project_code  # 项目编号
personnel.save()
```

### PersonnelAllocation (人员分配记录)
```python
# 创建完整的分配历史
allocation = PersonnelAllocation.objects.create(
    allocation_code='ALLOC20260321...',
    personnel=personnel,
    personnel_code=personnel.personnel_code,
    from_project=old_project,  # 原项目
    to_project=project,        # 新项目
    allocation_position=position,
    allocation_status='allocated',
    operator=request.user.username,
)
```

### Project (项目)
```python
# 通过 related_personnel 属性自动获取最新人员
@property
def related_personnel(self):
    return Personnel.objects.filter(
        project_code=self.project_code
    ).order_by('-entry_time')
```

## API 接口

### 1. 批量分配到项目
**URL**: `/personnel/allocations/allocate-ajax/`  
**方法**: POST  
**请求体**:
```json
{
    "personnel_ids": [1, 2, 3],
    "project_code": "PRJ001",
    "position": "技术员",
    "allocation_date": "2026-03-21"
}
```

**响应**:
```json
{
    "success": true,
    "message": "成功分配 3 名人员到项目 XX 项目",
    "allocated_count": 3
}
```

---

### 2. 批量分配到部门
**URL**: `/personnel/allocations/assign-department-ajax/`  
**方法**: POST  
**请求体**:
```json
{
    "personnel_ids": [1, 2, 3],
    "department": "工程部"
}
```

**响应**:
```json
{
    "success": true,
    "message": "成功将 3 名人员分配到部门 工程部",
    "updated_count": 3
}
```

---

### 3. 单个人员召回
**URL**: `/personnel/allocations/recall/<person_id>/`  
**方法**: POST  

**响应**:
```json
{
    "success": true,
    "message": "已成功召回人员 张三"
}
```

## 权限控制

- ✅ **查看权限** - 所有登录用户可访问可视化分配页面
- ✅ **操作权限** - 仅超级用户 (`is_superuser`) 可执行分配、召回操作
- ✅ **AJAX 接口保护** - 所有 AJAX 接口都有 `@user_passes_test(is_superuser)` 装饰器

## 使用场景示例

### 场景 A：新开工项目人员组建
1. 项目经理需要为新建项目配置团队
2. 进入可视化分配页面
3. 从"待分配人员"中筛选合适人员
4. 批量选择后分配到项目
5. 系统自动更新所有相关数据

### 场景 B：项目完工人员撤回
1. 项目完工，需要将人员调回公司
2. 在"已分配人员"中找到该项目的人员
3. 批量勾选后点击"召回"
4. 人员回到待分配状态，等待下次分配

### 场景 C：部门调整
1. 公司进行组织架构调整
2. 批量选择某个部门的人员
3. 统一调整到新部门
4. 不影响项目分配状态

## 注意事项

1. **分配前准备**
   - 确保人员基本信息完整
   - 建议先分配到部门，再分配到项目

2. **项目选择**
   - 必须选择有效的项目
   - 项目必须已存在于系统中

3. **日期设置**
   - 分配日期默认为当天
   - 可根据实际情况调整

4. **权限要求**
   - 只有超级用户可执行分配操作
   - 普通用户只能查看

5. **数据备份**
   - 批量操作前建议备份数据
   - 可通过导出功能保存当前状态
