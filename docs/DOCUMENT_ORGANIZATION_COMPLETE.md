## 🔄 文档维护流程

### 新增文档流程
1. **创建文档** → 在项目根目录创建 `.md` 文件
2. **确定分类** → 判断文档类型和所属分类
3. **移动到目录** → `move 文件名.md docs\分类目录\`
4. **更新索引** → 在 `docs/README.md` 中添加记录

### 文档更新原则
- **重大变更** → 创建新版文档，保留历史版本
- **小幅修改** → 直接更新原文档
- **过时内容** → 添加"已废弃"标记或移至归档目录

### 定期维护
- **每月检查** → 清理过时文档
- **版本迭代** → 更新相关功能文档
- **索引同步** → 保持索引与实际文件一致

## 💡 最佳实践

### 文档命名规范

**英文文档：**
```
FEATURE_TYPE_DESCRIPTION.md
示例：CONTRACT_LEDGER_FIELDS_OPTIMIZATION.md
```

**中文文档：**
```
功能名称_说明类型.md
示例：人员管理模块_快速访问指南.md
```

### 文档结构建议

1. **标题明确**：一眼看出文档主题
2. **目录清晰**：包含章节导航
3. **代码示例**：提供可运行的代码片段
4. **截图说明**：复杂操作配流程图或截图
5. **参考资料**：列出相关文档链接

### 文档组织技巧

- **单一职责**：一个文档只讲一个主题
- **层次分明**：使用标题分级（# ## ###）
- **列表展示**：多用无序/有序列表
- **重点标注**：使用粗体、引用块强调重点
